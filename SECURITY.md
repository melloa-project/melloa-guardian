# Security policy

Report Guardian vulnerabilities privately through GitHub's private vulnerability reporting or a private channel controlled by the repository owner. Do not publish exploit details before a fix and recovery guidance are available. Only the current `main` revision is supported before a tagged release.

Never include real credentials, recovery material, host addresses, personal data, or production logs in an issue or pull request.

The Guardian never accepts model reasoning as authority. Signature bypass, journal-chain bypass, unsafe transition, key exposure, privilege-boundary failure, and a path for the Melloa runtime to mutate Guardian state are release-blocking issues.
